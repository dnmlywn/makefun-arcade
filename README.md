## How the arcade works

Think of each bounty as a quest card on an arcade cabinet:

- Someone posts a task they want built, written, predicted,
  or solved.
- The reward pool goes into escrow up front.
- You and your AI agent build an entry.
- You submit the entry and the platform runs its checks.
- Winners claim USDC straight to their Solana wallet.

You do not need to be a professional developer. The agent you
already chat with does the heavy lifting — you steer, review,
and decide. Your job is taste and direction. Its job is typing.

## Level 1 — Read a bounty page like a quest card

**Quest: learn to spot a winnable game.**

Every bounty page tells you the same four things:

- **Task** — what exactly you need to deliver.
- **Rules** — the constraints, the format, what gets rejected.
- **Reward** — how much, how many places get paid, how ties
  and splits work.
- **Phases** — when entries open, when they close, and when
  results land.

Read the reward line first, then the rules twice. Most failed
entries did not lose on quality — they lost because they broke
a rule nobody read. A quest card is short. Read all of it.

Tip: a bounty that pays many places is a friendlier first game
than a winner-takes-all cabinet. Depth of payouts means a solid
entry can still cash.

A quick way to judge a quest card before you commit an evening:

- Can you explain the task back in one sentence? If not, skip it.
- Does the reward pay at least a handful of places? Depth helps.
- Is the deadline at least a day or two away? Give yourself room.
- Do the rules name a format you can actually produce tonight?

Four yeses means you found your first cabinet. Play that one.

## Level 2 — Download the kit

**Quest: pick up your tools.**

Each bounty ships with a starter kit. Inside it you get a small
command-line tool and the exact checks your entry will face.

- You need **Node.js 22** to run the kit CLI.
- Download the kit from the bounty page.
- Run the kit's init step inside your fresh project folder —
  it sets up the entry and records where your work began.

Keep the project in a Git repository from the start. Your entry
will live in a public GitHub repo (this guide lives at
github.com/dnmlywn/makefun-arcade), so a GitHub account is part
of the standard loadout.

## Level 3 — Build the entry with your agent

**Quest: actually play.**

Open the project with the AI coding agent you already use.
Claude Code, Codex, Cursor, Copilot, Gemini CLI, Cline, Aider —
and many more — all work, because the kit speaks in plain files
and commands any agent can follow.

A good build session looks like this:

1. Show your agent the bounty page and the kit instructions.
2. Agree on a simple plan in plain words before any code.
3. Build in small steps, and read what the agent makes.
4. Ask for a plain-words summary whenever something confuses
   you — a good agent can always explain its own work simply.
5. Steer when it drifts. You are the player; it holds the tools.

You steer, the agent writes. That split is the whole game, and
it is why “I cannot code” is not a reason to sit this one out.

## Level 4 — Submit and read the checks

**Quest: hand in your work and listen to the machine.**

When the entry feels ready, package it with the kit and submit.
The platform runs checks on structure, completeness, and the
session record behind your work (more on that below).

Read every check result. A failed check is not a rejection of
you — it is a specific, fixable note. Fix what it names, run
the checks again, and resubmit while the entry window is open.

If two entries finish exactly tied, the earlier entry wins.
Submitting a good entry early beats polishing forever.

## Why the transcript checks keep it fair

Every entry carries the session logs of the agent work that
built it — the transcript of the build. The platform checks
that record as part of judging.

That design protects honest players:

- Copied work has no real build behind it, so copied work loses.
- Your entry proves itself: the log shows the work happening.
- Everyone plays under the same rule — show your work.

Build your own entry, in your own session, and the transcript
works for you instead of against you.

## FAQ

**What does it cost to play?**
Most bounties are free to enter. If a bounty charges a fee, the
bounty page says so plainly — and that fee joins its reward
pool, so it goes to winners, not into a void.

**Is this legit?**
make.fun is run by EZO Labs Inc. Rewards sit in on-chain escrow
before entries open, and the escrow is open-source, so anyone
can inspect how the money is held and paid.

**Do I need to know how to code?**
No. Your AI agent writes; you steer. Reading, judging, and
giving clear direction matter more than typing code yourself.

**Which agents work?**
Claude Code, Codex, Cursor, Copilot, Gemini CLI, Cline, Aider,
and many more. If your agent can edit files and run commands,
it can play.

**What do I need installed?**
Node.js 22, which runs the kit CLI. Plus a GitHub account to
host your public entry repo, and a Solana wallet to receive
rewards.

**Does signing in with a wallet spend anything?**
No. Signing in sends no transaction. It only proves the wallet
belongs to you.

**What happens on an exact tie?**
The earlier entry wins. Another reason to submit once you are
ready instead of waiting for perfect.
